Guía de configuración

Sigue estos tres pasos para conectar claude.ai con tu Odoo. Tiempo estimado: 5 minutos.

1
Instala el módulo y activa la licencia
  1. Ve a Aplicaciones en Odoo, busca IA Agents Treasury Control e instálalo.
  2. Una vez instalado, ve a Ajustes → IA Treasury Control → Licencia SaaS.
  3. Introduce tu clave de licencia (formato XXXX-XXXX-XXXX-XXXX) y pulsa "Validar licencia ahora".
  4. El campo Estado debe cambiar a Activa.
Si aún no tienes clave de licencia, contacta con info@uniasser.com.
2
Copia los datos de conexión desde Odoo

En Ajustes → IA Treasury Control → Conectar con claude.ai verás tres valores generados automáticamente al instalar el módulo:

URL del servidor https://tuodoo.com/mcp
OAuth Client ID nombre_de_tu_base_de_datos
OAuth Client Secret a3f8c2d1e5b7… (generado automáticamente)

No tienes que generar ni configurar nada — el módulo lo hace solo al instalarse.

3
Añade el conector en claude.ai
  1. Abre claude.ai y ve a Settings → Integrations.
  2. Pulsa "Add custom connector".
  3. En Name escribe, por ejemplo, Mi Odoo.
  4. En Integration URL pega la URL del servidor del paso anterior (p. ej. https://tuodoo.com/mcp).
  5. Despliega "Advanced settings" e introduce:
    • OAuth Client ID: el valor del paso 2
    • OAuth Client Secret: el valor del paso 2
  6. Pulsa "Add".

Claude se autenticará automáticamente vía OAuth y tendrás acceso a todas las herramientas financieras.

¿Lo tienes? Prueba ahora: abre un chat en claude.ai y escribe "¿Cómo está la tesorería esta semana?" — Claude consultará tu Odoo y te responderá con los datos reales de tu empresa en segundos.

¿Necesito configurar algo en el servidor? Casi nada. El módulo se autoconfigura al instalarse. Solo tienes que copiar los datos de Ajustes y pegarlos en claude.ai. Si usas nginx como proxy inverso, añade proxy_buffering off para la ruta /mcp (ver sección "Administradores de sistema" más abajo).

¿Necesito una cuenta de Anthropic o API Key? No. El módulo funciona con tu cuenta de claude.ai habitual (plan Pro o Team). No necesitas API Key ni pagar nada adicional a Anthropic.
¿Funciona desde el móvil? Sí. La app oficial de Claude (iOS y Android) también soporta conectores MCP con autenticación OAuth.
¿Qué pasa si regenero el token? Tendrás que actualizar el OAuth Client Secret en claude.ai con el nuevo valor. El botón "Regenerar token" en Ajustes te genera uno nuevo en un clic.

¿Funciona también desde WhatsApp? Sí, configurando n8n para reenviar los mensajes al endpoint /webhook/whatsapp. Contacta con info@uniasser.com para la guía de configuración.
¿Funciona con Odoo Community (CE)? Sí. El módulo es compatible con las versiones Community y Enterprise de Odoo 16, 17, 18 y 19.
¿Cómo se renueva la licencia? La licencia SaaS se renueva automáticamente cada mes. Recibirás un aviso por email antes del vencimiento. Si la licencia caduca, el módulo entra en modo suspendido hasta que se renueve.
⚙️ Configuración avanzada — para administradores de sistema

Requisito: nginx con SSE habilitado

Si Odoo está detrás de un proxy inverso nginx (instalación habitual), el endpoint /mcp necesita que el proxy no almacene en búfer la respuesta para soportar Server-Sent Events (SSE). Sin esto claude.ai no puede recibir la respuesta del servidor.

Añade este bloque en la configuración nginx de tu dominio Odoo, antes del location / genérico:

location = /.well-known/oauth-protected-resource {
    proxy_pass http://127.0.0.1:8069/.well-known/oauth-protected-resource;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location /mcp {
    proxy_pass http://127.0.0.1:8069/mcp;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_cache off;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Connection '';
    proxy_read_timeout 300s;
}

Recarga nginx tras el cambio:

sudo nginx -t && sudo systemctl reload nginx

proxy_mode en odoo.conf

Si usas nginx como proxy inverso, asegúrate de que tu odoo.conf incluye:

proxy_mode = True

Esto permite a Odoo leer correctamente las cabeceras X-Forwarded-*.

server_wide_modules

El módulo debe cargarse como server-wide para responder a rutas OAuth antes de que Odoo resuelva la base de datos. En odoo.conf:

server_wide_modules = base,web,ia_agents_treasury_control

dbfilter recomendado

Si tu Odoo gestiona varias bases de datos, añade en odoo.conf:

dbfilter = ^nombre_de_tu_bd$

Garantiza que Odoo siempre resuelve la base de datos correcta en las peticiones MCP.

Verificar que el módulo está activo

# En el servidor, comprueba que el proceso Odoo tiene el módulo cargado:
curl -s https://tuodoo.com/.well-known/oauth-protected-resource | python3 -m json.tool

Si ves un JSON con "resource" y "authorization_servers", el módulo está activo.
